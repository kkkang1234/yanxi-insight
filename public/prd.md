# 言析 Insight：AI 用户访谈洞察助手

> 中文 MVP 产品需求文档｜版本 1.3｜更新日期：2026-09-23  
> 用途：产品设计、研发与验收的需求基线。

## 1. 产品定位与目标

言析 Insight 面向工作场景中的用户研究员、产品经理和设计师，帮助他们把零散访谈材料整理为围绕研究问题、可逐条追溯原文的产品洞察，支持需求判断、产品迭代和设计决策。核心价值是缩短“理解背景—阅读访谈—归纳发现—检查证据—形成产品判断”的过程，并保留研究者的判断权。

**一句话定义：**基于研究背景和访谈大纲，识别访谈中的多个话题、任务阶段与行为痛点，跨受访者归纳发现，并生成附带原文证据的洞察和设计机会。

### 1.1 产品边界与运行约束

- 核心使用场景为产品与设计工作中的定性访谈分析，覆盖需求探索、任务流程诊断和迭代方案研究。
- 应用运行需要独立验证模型提供方、服务端调用方式、凭证机制、额度及限制；不同运行环境的模型能力不能视为天然一致。
- 所有“自动提取、自动归纳、生成洞察”必须来自真实成功的模型调用。接口不可用时明确显示不可用，并允许手工完成；不得用定时器、固定返回值或样例替代真实 AI 成功状态。
- 产品第一版面向单人、小规模研究项目，不承担企业级协作、无限批量或统计推断任务。

### 1.2 成功标准

用户能使用自己的访谈材料，完整完成一次：创建项目 → 确认背景与研究问题 → 导入并标注访谈 → 按话题和阶段查看跨受访者发现 → 逐人核对原文 → 编辑确认洞察 → 导出 Markdown 报告。

最低可交付版本必须使这一闭环真实可用。自动分析尚未通过真实调用验收时，应在研发验收记录中说明限制；产品不展示“人工整理模式”“模型未配置”等开发环境标签，也不得伪造自动分析成功。服务不可用时，在操作发生处给出清晰的失败反馈并保留输入。

### 1.3 产品验证指标

首轮验证关注：是否完成端到端任务、引用精确匹配通过率、无效引用进入正式报告的数量、受访者计数正确性、用户是否能独立回查和修正结论。正式报告中无效引用应为 0，验收夹具人数必须完全正确。

“节省整理时间”和“提升研究质量”是待验证的产品价值，不是已取得的效果。后续可用同一组材料比较手工整理与使用产品的耗时，并记录研究者对发现和洞察的接受、修改、删除情况；不设未经验证的效率提升百分比。

## 2. 用户、问题与典型场景

核心用户是在企业或专业服务项目中承担访谈分析和产品决策工作的人员。MVP 支持个人完成研究分析并导出结果，供团队在评审、需求讨论和设计决策中使用；团队内实时协作不属于本版范围。

| 用户 | 现有困难 | 本产品支持 |
|---|---|---|
| 用户研究员 | 多份访谈编码、跨人归纳和原文核对耗时，结论容易脱离研究问题 | 大纲引导分析、开放发现、跨人聚合与证据追溯 |
| 产品经理 | 难以把访谈中的零散反馈转为有依据的需求判断，评审时缺少可回查材料 | 围绕研究问题形成产品判断、待验证假设和证据报告 |
| 用户体验 / 交互 / 服务设计师 | 用户在不同任务阶段的行为与痛点分散，设计方向缺少清晰依据 | 按主题和任务阶段整理行为痛点，连接洞察与设计机会 |

**典型场景：**产品团队正在研究某项任务为何频繁中断。负责分析的用户研究员、产品经理或设计师提供业务背景、研究问题和访谈大纲，导入 3—5 份访谈文本。系统识别每位受访者在了解、尝试、完成等阶段的不同经历，聚合同类问题；分析人员点击卡片逐人检查引文，保留分歧，最终导出回答研究问题的报告，用于需求评审和迭代设计讨论。

上述阶段仅为说明性例子，不是所有项目的固定阶段。本文中的示例和验收夹具均为合成材料，不代表真实用户研究结论。

## 3. 范围与优先级

P0 为闭环必需；P1 为核心稳定后增加的便利能力；不通过缩减证据可靠性来换取界面丰富度。

| 优先级 | 能力 | 范围 |
|---|---|---|
| P0 | 项目创建与 AI 辅助整理 | 文字输入、上传或粘贴大纲，提取背景、目标、对象、研究问题，来源与缺失冲突提示，人工确认 |
| P0 | 访谈导入 | 单份 / 多份 Word（DOCX）、TXT、MD 或粘贴文本，预览、受访者标注、重复提醒、逐份状态 |
| P0 | 大纲引导与开放发现 | 优先匹配大纲主题，同时发现大纲外话题；无大纲时开放归纳 |
| P0 | 单访谈多维分析 | 多话题、任务链路阶段、行为、痛点；未知阶段可以留空 |
| P0 | 跨访谈聚合 | 按主题与阶段聚合，唯一受访者计数，保留反例与单人信号 |
| P0 | 证据查看和校验 | 卡片触发右侧栏，逐人展示原话，定位全文，精确引用校验 |
| P0 | 洞察链与人工审核 | Evidence → Finding → Insight → 产品判断 / 设计机会 / 待验证假设；编辑、确认、撤销确认 |
| P0 | 项目管理与保存 | 新建项目、历史项目切换、自动保存，刷新后保留原文与分析 |
| P0 | 洞察报告下载 | 下载包含有效已确认内容与证据附录的 Markdown 报告 |
| P0 | 真实运行状态 | 处理中、失败提示、重试与过期状态；模型配置和运行日志属于研发运维，不进入日常产品导航 |
| P1 | 浏览器语音输入 | 检测支持后启用，转写为可编辑文字，再参与背景提取 |
| P1 | 更多文本格式 | PDF 等格式仅在解析可验证后支持；旧版 DOC 提示转存 DOCX |
| P1 | 阅读便利 | 主题合并、批量确认、更多筛选、报告样式优化 |
| 不做 | 复杂研究工作台 | 复杂用户画像、同理心地图、旅程地图可视化编辑器、地图 |
| 不做 | 重型平台能力 | 登录权限、多用户协作、云端同步、向量数据库、复杂检索、自动发布 |
| 不做 | 音视频处理 | 音频文件 ASR、说话人分离、录音存储；浏览器语音不可用时采用文字输入 |

“任务链路阶段”保留为标签及分组视图，不扩展为旅程地图编辑器。没有大纲是正常使用路径，不是异常。

## 4. 核心业务规则

### 4.1 研究背景先于洞察生成

输入来源可以包括：研究者文字说明、浏览器转写后经研究者接受的文字、访谈大纲。系统提取：项目名称、业务背景、研究目标、访谈对象、核心研究问题、主题及可选阶段。

- 每个提取字段标注来源；来自大纲时可查看对应片段，来自输入时保留输入来源。
- 用户未提供的内容标注“待补充”，不得自动编造业务指标、用户数量或业务现状。
- 互相矛盾的输入并列呈现，标注“待确认”；不得静默选取某个版本。
- 人工改写标注“人工编辑”，原始输入仍保留。模型建议的研究问题标注“AI 建议”，不得显示为原文事实。
- 开始 AI 分析前，至少确认研究目标、访谈对象描述和一个研究问题；背景信息不完整允许继续，但持续提示分析限制。
- 核心字段冲突必须由用户选择、改写或明确记录“暂未解决”后才能继续。未解决项进入后续分析限制。
- 上传大纲不等于所有大纲问题都已在访谈中回答。

### 4.2 一个访谈可以对应多个话题与阶段

按有意义的片段分析，不给整份访谈强行贴一个唯一标签。一个片段可对应多个主题、研究问题或痛点；同一受访者可谈及多个阶段。

主题来源分为：大纲主题、开放发现、人工添加。阶段来源分为：大纲 / 项目已确认、访谈中提出的候选阶段、人工添加。阶段缺少依据时显示“阶段待确认”，不套用通用营销漏斗。

有大纲时先尝试匹配，不能匹配的有价值片段进入“大纲外话题”；无大纲时自动归纳候选主题，由用户改名或确认。话题不应强行等同于某个功能。

行为描述与痛点分别存储：发生某行为不自动代表有痛点；用户表达愿望不自动代表存在普遍需求。采访者的问题不作为受访者的陈述证据。

### 4.3 按主题和阶段跨受访者聚合

聚合对象是有证据支撑的发现，不只是相似关键词。默认以大纲问题方向分组，集中比较需求和痛点；阶段为可选补充，不要求二维地图。

- 卡片显示发现摘要、主题、阶段、相关研究问题、提及人数、证据片段数和审核状态。
- `提及人数 = 当前卡片有效支持证据关联的不同 participant_id 数量`。同一个人说三次仍计 1 人；同一个人的多份访谈仍计 1 人。
- `证据片段数`按去重后的有效引用计算，不能与人数混用。
- 默认分母是当前分析范围内已成功分析且身份已确认的受访者人数；显示“2 / 4 位已分析受访者提及”，同时列出失败或未处理材料数。
- 分母不代表被问过同一问题的人数，因此不能把未提及解释为“不存在痛点”，不能推断总体发生率。
- 筛选改变样本范围时，人数与分母同步重算。P0 不显示容易造成误解的百分比图。
- 支持、反对 / 反例、补充背景分别标注；反例不能算进支持人数，未提及也不是反对。
- 单人信号可以保留并明确标为单人发现，不能为了生成洞察把它包装成普遍规律。

### 4.4 输出层次必须分离

| 层次 | 定义 | 必需关联 | 禁止的跳跃 |
|---|---|---|---|
| Evidence 证据 | 受访者在特定位置的原话 | 受访者、文本版本、位置、精确引文 | 把摘要伪装成原话 |
| Finding 发现 | 对现象 / 行为 / 痛点的归纳 | 至少 1 条有效证据、人数 | 无证据声称“多数人都……” |
| Insight 洞察 | 对现象背后需求或机制的解释 | 至少 1 条发现、研究问题、解释局限 | 把研究者推测说成用户明确表达 |
| 产品判断 | 对优先考虑、暂缓或继续研究的判断 | 洞察及理由、限制 | 直接宣称会提升转化或留存 |
| 设计机会 | 值得探索的改善方向 | 洞察、对应问题、预期价值假设 | 把唯一方案写成必然答案 |
| 待验证假设 | 尚不能确认但值得验证的命题 | 已有线索、待验证内容、方法及判定信号 | 伪造已验证效果或因果关系 |

不是每条证据都必须生成洞察，也不是每条洞察都必须有三个下游输出。证据不足时允许显示“暂不足以形成解释”，或生成明确标注的待验证假设。MVP 不输出模型自评的精确置信度百分比。

## 5. 页面与关键交互

采用一个应用内的四个主视图，对应项目准备、材料管理、证据分析和结论输出。宽屏为主；窄屏证据栏可覆盖主区域。

### 5.0 信息架构与导航

- 一级侧栏只承担项目管理：品牌、新建项目、历史项目列表。历史项目显示名称、访谈数量和已确认洞察数量，当前项目高亮；不再重复列出研究准备、访谈材料、分析与报告入口。
- 历史项目按最近更新时间排序。切换项目时只改变当前工作对象，已保存的材料和分析保留，并进入该项目已有进度对应的步骤。
- 当前项目的二级导航固定为“01 研究准备 → 02 导入访谈 → 03 分析与核对 → 04 确认与导出”，保留四步结构。
- 新建项目先输入名称，创建后进入研究准备。项目名称可在研究准备页修改；删除项目采用独立危险操作和二次确认。
- 产品不设置模型供应商、API 密钥、额度、接入状态、运行日志或演示工具的导航项。相关配置与验证在服务端和研发文档中管理。
- 产品不提供项目备份、JSON 下载、备份恢复或原始存储下载。面向用户的下载能力仅为洞察报告；项目持续使用依靠自动保存和历史项目列表。
- 同一页面只突出当前阶段的主要动作，避免在标题区、空状态和底部重复堆叠同一按钮。窄屏切换历史项目后收起侧栏。

### 5.1 项目页：创建与背景确认

**入口：**新建项目 / 从历史项目列表打开已有项目。

布局：左侧输入研究说明与上传大纲，右侧结构化项目草稿。

1. 用户输入说明；可以粘贴大纲或上传 DOCX / TXT / MD。语音按钮仅在支持时显示或明确说明不可用。
2. 点击“整理研究信息”，显示真实处理状态；用户可取消并保留输入。
3. 草稿展示背景、目标、对象、研究问题。每项旁显示“来源”“AI 建议”“待补充”或“冲突”。
4. 用户编辑、删除或新增研究问题；点击“确认并继续”。
5. 自动整理失败时提示“本次整理未完成，内容已保留，请稍后重试”；用户仍可编辑字段，不展示接入环境或密钥配置说明。

语音输入是将口述转为文字的便利入口，转写文字必须可修改，不在用户未点击时开始录音；拒绝权限、浏览器不支持、转写中断均回到文字输入，已经获得的文字保留。具体支持环境需开发时实测。

### 5.2 材料页：受访者记录与初步整理

上传 Word（DOCX）、MD、TXT 或粘贴文字，支持批量。每份文件是一条独立访谈者记录，显示文件名、受访者编号、字数和整理状态。自动分配不重复别名，用户可修改；同一人多次访谈使用相同编号，不因多文件重复计人数。完全相同的文本拦截重复导入，一份文档包含多名被访者时要求拆分。

点击“查看整理记录”，默认按访谈大纲的问题方向作为标题，拆分展示提问和对应回答。无大纲时使用已填写的主题或研究问题；无法可靠匹配的内容进入“其他话题 / 待归类”，不强行匹配。允许调整段落归属。

整理稿与完整原文并存。初步清理只处理独立的“嗯、呃、额”等犹豫语气词，不删除“不、没有、可能、我觉得”等影响含义的表达，不改变数值、态度或因果关系。用户可编辑整理稿并展开对照原文；证据始终引用原文，而不是整理后的改写内容。

记录页不再显示主题、任务阶段、行为、痛点、证据角色等密集标注表单，不要求逐句添加发现。保留按问题整理、完整原文、编辑文字、归类调整和确认整理完成。

### 5.3 分析页：按问题方向综合需求与痛点

以大纲问题方向为章节标题，在每个方向下结合多位受访者的内容，归纳分析结论、用户需求与行为、主要痛点及差异。相关分析集中在同一章节，避免按每句话生成碎片卡片。可展开查看该方向对应的访谈记录；未形成结论时明确保留空态。

“整理需求与痛点”允许研究者填写综合结论、关联研究问题，并选择同方向的一段或多段原文作为依据。引用前确认说话人与证据含义；仅在至少有一条有效依据时允许保存。自动分析不能以关键词命中冒充语义理解。

点击“查看证据”在右侧展开证据栏：显示分析结论与研究问题、支持人数、反例、有效片段，并逐受访者展示原话、文件与来源。点击“定位全文”打开原文并高亮确切引用。无效引用必须提示失效，不能用近似位置冒充成功。支持、反例、背景分开计数；同一人多份记录不重复计人数。

分析仍可编辑和确认，修改后重新校验并撤销相关报告确认。任务阶段作为可选补充属性，不占用主流程必填位置。

### 5.4 确认与导出：完整分析报告

页面呈现一篇连续报告，结构为：研究背景与样本范围 → 核心结论摘要 → 各研究问题的完整章节 → 研究限制。各章集中呈现用户需求与痛点、综合解释、产品判断、设计建议及待验证假设，而不是再次堆叠碎片发现卡片。

- 每个问题对应一个可编辑、可确认的报告章节；已有多条洞察在页面中按字段整合展示，编辑保存为一个章节。
- 底层发现与原文位于可展开的“分析依据与受访者证据”中，默认突出报告正文。
- 编辑已确认章节会撤销确认；背景、资料或依据改变时要求重新核对。
- 生成报告内容只允许使用已确认发现及有效证据，不得自动把设计建议当作受访者原话。
- 仅保留“下载洞察报告”，导出 Markdown 的正文同样按完整章节组织，附精确引用证据。未确认、失效的结论不能进入正式报告。
- 材料不足的章节保留缺口，不补写无依据结论；未完成的章节仍在工作区内编辑。

## 6. 文本、引用与去重规则

### 6.1 支持格式和工作量边界

MVP 承诺 Word（DOCX 正文）、UTF-8 的 TXT、MD 与粘贴文本。DOCX 提取正文与表格中的可读文字，不执行宏；不支持旧版 DOC、加密文件、扫描图片或嵌入对象中的内容，需转换后导入。单文件不超过 5 MB。Markdown 作为纯文本处理，不执行嵌入 HTML、脚本或远程资源。PDF、扫描件、图片、音频、视频默认不支持，提示转换为文本后导入。

初始验收规模：每项目最多 5 份访谈，每份最多 20,000 个字符，总计不超过 60,000 个字符；大纲最多 10,000 个字符。该限制是产品验收边界，不是未经验证的模型上下文承诺。接入验证发现限制更低时，应在界面与交付说明中同步调低，不可静默截断。

空文本、解码异常、超长文本均在分析前拦截。分段只用于处理模型上下文，不改变全文内容；超出可处理范围时明确告知并让用户拆分。

### 6.2 精确引用

1. 导入时保留原始输入，另建立标准文本：只统一换行符和移除文件头 BOM，不做改写、翻译或自动纠错。
2. 引用统一针对标准文本版本；全文展示也使用这一版本，保留稳定段落编号。
3. 每条证据存储文档 ID、版本、段落 ID、起止字符位置和引文；位置采用统一的 UTF-16 字符串索引、左闭右开区间，前后端必须遵守同一规则。
4. 模型返回段落 ID 和连续原话，应用自行查找精确位置；不能仅信任模型生成的数字位置。
5. 硬校验要求：`标准文本.slice(start, end) === quote`。多处完全匹配时结合段落与上下文定位；仍有歧义则待人工确认。
6. 省略内容不能被拼成一条连续引文；需要拆成多条证据。摘要可改写，引文必须逐字一致。
7. 校验失败的引文可以作为错误候选供排查，但不进入正式证据、人数计算或正式报告。
8. 精确匹配只能证明“文本里有这句话”，不能证明“这句话支持该结论”。界面分别显示“原文匹配通过”和“人工确认支持关系”，不可用一个绿色标记替代两者。

### 6.3 去重、身份与版本

- 文档级：标准文本哈希用于检测完全重复材料，不作为自动合并不同受访者的依据。
- 引用级：同一标准来源、版本与相同区间为同一证据；多个分块提取到相同证据只保留一次。
- 重叠区间仅在同一来源、语义相同且属于同一连续表述时归并；不自动拼接不同句子，不删掉同句中的不同问题。
- 卡片级：同一证据可以支持多个不同发现；各卡片独立计算人数，不能把卡片人数相加得出项目总人数。
- 原文导入后只读；替换文本产生新版本，不覆盖旧版本。旧版证据保留用于追溯，但当前报告中的关联条目标为过期，重新分析并审核后恢复。
- 项目背景、大纲、研究问题或受访者身份改变时，相关分析标为待复核；不能沿用旧“已确认”状态。

## 7. 数据模型与状态

以下为逻辑模型，不规定具体数据库或编程框架。单人 MVP 可采用本地持久化，具体实现以后续技术验证为准。

| 实体 | 核心字段 | 关系 / 约束 |
|---|---|---|
| Project | id、name、background、objective、targetDescription、contextVersion、status、createdAt、updatedAt | 包含研究问题、材料和分析 |
| ContextFieldSource | field、sourceType、sourceId、sourceSpan、value、issueType、resolution | 支持人工输入、大纲、转写文字、AI 建议；记录缺失和冲突 |
| ResearchQuestion | id、projectId、text、source、status | 被发现和洞察引用 |
| Outline | id、projectId、rawText、canonicalText、version | 大纲不是受访者证据 |
| Participant | id、projectId、alias、optionalNote | 身份由用户确认，作为人数去重键 |
| Interview | id、projectId、participantId、fileName、sourceIdentity、rawText、canonicalText、hash、version、status | 一次访谈一名被访者；副本关联 sourceIdentity |
| Segment | id、interviewId、version、paragraphId、start、end、speakerRole、direction、cleanText | 连续原文位置；整理稿独立保存；角色含采访者、受访者、未知 |
| Theme | id、projectId、label、origin、outlineRefs、status | 大纲主题 / 开放发现 / 人工添加 |
| Stage | id、projectId、label、order、origin、status | 不确定可不关联，不能强填 |
| Evidence | id、interviewId、version、participantId、segmentId、start、end、quote、validationStatus | 必须精确匹配原文 |
| Observation | id、themeIds、stageIds、behavior、painPoint、evidenceIds | 一个片段可产生多条观察，行为与痛点可分别为空 |
| Finding | id、summary、questionIds、themeIds、stageIds、evidenceLinks、reviewStatus、dependencyVersion | evidenceLinks 包含支持 / 反例 / 背景；人数从证据派生 |
| Insight | id、questionIds、findingIds、interpretation、limitations、reviewStatus、dependencyVersion | 不直接脱离发现生成 |
| Implication | id、insightIds、type、text、rationale、validationMethod、successSignal、reviewStatus | type 为产品判断 / 设计机会 / 待验证假设 |
| AnalysisRun | id、projectId、scope、contextVersion、inputVersions、step、providerLabel、promptVersion、status、error、timestamps | 记录真实调用结果，不保存密钥 |
| ExportSnapshot | id、projectId、mode、includedIds、versions、createdAt | 记录导出范围和时间，便于复现 |

**材料状态：**待确认 → 可分析 → 处理中 → 成功 / 部分成功 / 失败；修改依赖后可变为待重新分析。

**分析条目状态：**AI 草稿 / 人工草稿 → 已确认 → 待复核；删除或排除不再进入报告。证据的校验状态与结论的审核状态分开。

持久化要求：编辑后自动保存并显示状态；失败时保留当前页面数据，提示暂勿关闭页面并允许下载已有洞察报告。刷新后恢复已保存项目，读取时校验数据版本、结构与引用关系；异常时不得静默覆盖历史数据。删除项目需要明确确认。MVP 使用当前设备的存储，不承诺跨设备同步；不提供面向用户的项目备份或恢复功能。

## 8. AI 调用流程与防幻觉要求

### 8.1 环境验证门槛

开发首先验证本地实际可用的调用路径：是否有可供应用调用的模型服务、服务端请求方式、凭证来源、返回结构、超时 / 限流和额度。用一段明确标注的合成文字完成真实调用，并检查响应来自服务而非静态数据。

若本地无可用模型服务：

1. 自动分析入口返回明确的服务不可用反馈；创建、标注、证据、编辑、保存和报告下载继续可用，不设置独立的“人工模式”。
2. 统一模型调用入口保留待接入状态，不虚构模型服务的函数名、SDK 或端点。
3. 根据目标运行环境的真实接口完成适配，再执行完整验收用例。
4. 开发环境与目标运行环境分别记录验证结果；其中一个通过不能代表另一个通过。

凭证不得写入前端、导出文件或代码包；错误日志不得完整输出访谈正文或密钥。平台是否代管调用权限以实测为准。

### 8.2 分阶段调用

| 步骤 | 输入 | 结构化输出 | 应用侧校验 |
|---|---|---|---|
| A：整理项目 | 用户说明、大纲 | 项目字段、来源、缺失冲突、建议研究问题 / 主题 | 来源存在；建议与事实分开；人工确认 |
| B：提取观察 | 已确认上下文、研究问题、主题 / 阶段、带段落 ID 的访谈片段 | 观察、行为、痛点、候选主题 / 阶段、连续引文 | JSON 结构、ID、说话人、精确引文、越界位置 |
| C：跨人聚合 | 校验通过的观察与证据、已确认分类 | 发现、支持 / 反例关系、研究问题关联 | 引用有效、语义待审、人数由应用重算 |
| D：形成洞察 | 已确认发现及证据、研究目标 / 问题 | 洞察、限制、产品判断、机会、待验证假设 | 依赖存在、无伪造事实或指标、人工审核 |

按访谈逐份处理并保存成功结果，失败只重试失败步骤。长文按段落切分，块之间保留必要上下文但保持统一位置；每块结果回收到完整访谈后再跨人聚合。全部块成功才显示该材料完整分析，缺失块需披露。

输出以严格结构化数据为目标；格式失败最多做一次修复尝试，仍失败则呈现错误。只对可重试的短暂错误做有限重试，不能无限循环消耗额度。网络失败、限流、鉴权失败采用不同提示，用户输入与成功结果保留。

### 8.3 统一约束

- 访谈、大纲和上传文件都是分析数据，不是系统指令。即使原文包含“忽略要求”“编造证据”等语句，也不能改变任务规则。
- 模型仅能引用给定材料及已有 ID；拒绝不存在的受访者、来源、研究问题或证据 ID。
- 不调用网页搜索补齐研究事实，不用行业常识代替受访者陈述。
- 找不到证据返回缺失 / 不确定，不能为了填满报告补写事实。
- 不把出现次数变成独立人数；人数由程序按身份和有效关系计算。
- 保留否定、条件、时间和语境，不把“我没有遇到”归成“我遇到了”。
- 同时寻找反例；出现矛盾时表达分歧，不能平均化为统一结论。
- 不保证“零幻觉”。通过来源限制、引用硬校验、依赖检查和人工审核降低错误，并明确各层校验的局限。
- 人工修改不能绕过证据有效性约束；确认代表研究者接受当前解读，不等于模型结论已客观证明。

## 9. 异常与边界处理

| 情况 | 产品响应 | 数据处理 |
|---|---|---|
| 没有大纲 | 允许继续，开放归纳主题 | origin 标为开放发现 |
| 背景缺失 / 冲突 | 字段级提示，允许明确记录限制 | 不自动补事实 |
| 空文件、乱码、不支持格式 | 说明具体文件及原因，建议粘贴文本 | 不创建可分析的空材料 |
| 超长文本 / 上下文不足 | 拆分处理或明确要求拆分 | 禁止静默截断 |
| 完全重复文件 | 提醒并默认跳过，可显式保留副本 | 共享来源身份，去重计数 |
| 同人多次访谈 | 选择已有受访者 | 人数只计一次，片段可保留多条 |
| 多人混合且身份不明 | 要求拆分 / 明确标注 | 不猜测人数 |
| 采访者话语被提为证据 | 标为不合格或待确认 | 不计支持人数 |
| 引文不存在 / 位置歧义 | 待修复，提供全文核对 | 不进入正式报告 |
| 证据真实但不支持摘要 | 用户排除或修改支持关系 | 重新计算并撤销关联确认 |
| 没有痛点 / 没有新洞察 | 明确显示未发现足够依据 | 不强行生成卡片 |
| 只有一名受访者 | 允许分析，标明单人材料 | 不称作跨人共性 |
| 观点相互矛盾 | 并列呈现分歧和适用条件 | 反例与支持分开 |
| 一部分材料分析失败 | 显示部分完成，提供逐份重试 | 分母仅含成功样本，报告披露缺失 |
| 模型未配置 / 超时 / 限流 | 产品侧显示“分析服务暂不可用”“服务繁忙”或“分析超时”等可理解的反馈；技术原因记录于研发运维 | 保留输入，允许编辑、核对和重试 |
| 重复点击 / 旧调用晚返回 | 禁用同一运行的重复提交；校验运行 ID 和版本 | 旧结果不覆盖较新编辑 |
| 分析中更改上下文 | 取消或将返回结果标为旧版本 | 不自动确认为当前结果 |
| 替换 / 删除已引用材料 | 展示影响范围并确认操作 | 相关证据失效、下游待复核 |
| 本地保存失败 / 空间不足 | 提示暂勿关闭页面，可下载已有洞察报告 | 保留页面内容，不误报保存成功 |
| 刷新时任务尚未结束 | 恢复已有结果，未结束步骤显示中断 | 用户重试，不伪装继续运行 |

## 10. 隐私与内容处理

以受访者别名为默认显示；上传前提示去除不必要的姓名、联系方式等信息。MVP 不宣称已具备自动脱敏功能。调用前说明所选材料会被发送至当前已配置的模型服务，数据保留规则以该服务实际规则为准，不宣称“完全离线”或“绝不留存”。

本地项目不跨设备自动同步。报告下载前提示检查个人信息，报告只附所引用的证据，不默认附带全部访谈全文。不得把项目材料、真实凭证和日志中的敏感内容混入应用发布包。测试使用脱敏授权材料或明显标注的合成材料。

## 11. 导出要求

### 11.1 Markdown 研究报告

文件名建议：`项目名称_访谈洞察报告_YYYYMMDD.md`。报告按连续正文组织，不逐条重复洞察卡片。报告包含：

1. 项目名称、导出时间、报告状态（已人工确认）。
2. 研究背景、目标、对象、核心研究问题及尚未解决的背景限制。
3. 样本范围：受访者数量、材料数量、已分析 / 未分析 / 失败范围，大纲和文本版本。
4. 按研究问题组织的结论；无答案的问题也列出。
5. 发现、洞察、产品判断、设计机会和待验证假设，标明状态、证据 ID 和适用限制。
6. 反例与证据不足部分，说明定性样本不能代表总体比例。
7. 证据附录：证据 ID、受访者别名、来源文件、文本版本、段落 / 位置、原文、支持关系。

应用内点击证据可定位全文；导出的 Markdown 使用证据附录锚点。独立 Markdown 不承诺自动打开应用或包含未引用的全文。报告是研究成果，不承担项目数据恢复功能。

## 12. 验收标准

验收记录使用“通过 / 未通过 / 未验证”，不能将本节的预期结果当成已完成结果。P0 功能、模型真实性、证据可靠性都通过后，才能称为完整 AI MVP。

| ID | 用例 | 通过标准 |
|---|---|---|
| AC01 | 输入背景并上传含不同对象描述的大纲 | 提取字段有来源；缺失不编造；冲突并列，可人工处理后继续 |
| AC02 | 无大纲创建项目 | 可确认目标、对象和研究问题并进入分析，无强制大纲门槛 |
| AC03 | 同时导入 3 份有效文本与 1 份无效文件 | 有效材料保留；无效材料单独报错；受访者可逐份确认 |
| AC04 | 同人两份访谈、重复文件、同名不同人 | 重复不增加证据；同人只计 1；同名不同 ID 不擅自合并 |
| AC05 | 单份访谈包含 2 个主题和 2 个阶段 | 不被压成一个标签；片段可分别关联正确主题与阶段 |
| AC06 | 大纲内与大纲外话题同时出现 | 两者均被保留并区分来源，不把新话题硬塞进大纲 |
| AC07 | 未明确阶段的材料 | 展示阶段待确认，不生成无依据的完整链路 |
| AC08 | 点击问题方向中的查看证据 | 右侧栏按人分组显示全部对应有效引文、文件和位置 |
| AC09 | 点击原话定位全文 | 打开正确版本，精确高亮；中文、换行和 emoji 不导致位置漂移 |
| AC10 | 模型输出不存在、改写过或歧义引文 | 校验失败或待确认，不计数，不进入正式报告 |
| AC11 | 同一人重复表达，另有一人持反例 | 支持人数按唯一身份计算；反例不混入支持人数；片段数单列 |
| AC12 | 采访者问题与受访者否定回答 | 不把问题当事实；不把否定识别为正向痛点 |
| AC13 | 生成最终结论 | 围绕研究问题，洞察可回溯发现和证据；不虚构业务收益 |
| AC14 | 只有单人或材料不足 | 明确标注单人 / 信息不足；可以不生成洞察 |
| AC15 | 人工编辑已确认结论或替换原文 | 相关状态变为待复核，失效引用阻止正式导出 |
| AC16 | 模型断开、鉴权错误、超时、部分失败 | 显示真实状态；成功结果保留；可有限重试或手工继续 |
| AC17 | 自动保存、刷新和历史项目切换 | 原文、别名、关系和状态保留；引用与计数一致；不同项目数据不串联 |
| AC18 | 下载洞察报告 | 仅含有效已确认项；证据附录可回查；没有备份、JSON 或独立草稿下载入口 |
| AC19 | 分析服务不可用时操作 | 不展示伪造成功；反馈失败并保留输入；界面不出现模型配置、密钥、额度或开发平台信息 |
| AC20 | 真实模型接入验证 | 用授权材料完成 A—D 调用链，运行记录可查；开发环境和目标运行环境分别记录结果 |
| AC21 | 原文包含要求模型编造的指令 | 指令仅作为数据，不改变输出规则或生成虚构来源 |
| AC22 | 重复提交、分析中修改后旧请求返回 | 不生成重复分析，不覆盖用户新编辑，版本状态正确 |
| AC23 | 满足声明规模的材料 | 不静默丢文本；逐份进度可见；实际耗时和失败点如实记录 |
| AC24 | 浏览器不支持或拒绝语音（P1） | 保留文字输入并正常完成项目创建；不能阻断 P0 |
| AC25 | 导航与按钮走查 | 一级仅管理项目，二级保留四步；所有按钮均有明确动作、必要的前置校验与可见结果；已完成动作不允许无意义重复提交 |

### 12.1 最小合成验收夹具

研究问题：“用户完成表单前遇到了哪些阻碍？”大纲主题：“填写体验”；候选阶段：“填写”“提交”。

- P01 / 访谈 A：“填写时我不知道这一项该填什么。”“点提交以后，我不知道有没有成功。”
- P01 / 访谈 B：“上次说的提交反馈，我后来还是没看懂。”
- P02 / 访谈 C：“点提交以后没有提示，我又点了一次。”“除此之外，我想知道完成后去哪里查看记录。”
- P03 / 访谈 D：“提交后的提示很清楚，我没有重复点。”

预期：提交反馈不清的支持人数为 2，反例人数为 1，已分析受访者总数为 3；P01 两份材料不计成两人。填写理解障碍是另一个发现；完成后查看记录可作为大纲外候选话题，不强制归为填写阶段。上述原话仅用于测试，任何演示页面均需标注“合成示例”。

## 13. 实施顺序与资源受限时的降级策略

MVP 范围以核心用户任务是否闭环为依据。实施时先验证关键依赖，再完成分析与证据链，最后验证整体体验。研发资源或模型服务能力受限时，明确记录延期项及影响，不降低证据可信度。

| 顺序 | 工作 | 完成门槛 |
|---|---|---|
| 1 | 核实应用模型接入、运行环境、数据保存方案 | 真实最小调用通过，或确定人工模式并明确 AI 阻塞原因 |
| 2 | 项目创建、背景确认、文本导入、身份和持久化 | 自有材料可输入、保存、刷新恢复 |
| 3 | 观察提取、引文校验、去重、跨人发现 | 原话精确匹配，计数正确，失败状态可见 |
| 4 | 分析卡片、证据栏、全文定位、人工编辑 | 卡片 → 按人证据 → 全文闭环通过 |
| 5 | 洞察链、确认、Markdown 报告下载 | 报告可回查证据，项目自动保存 |
| 6 | 用真实调用与合成边界材料验收 | 记录通过、失败、限制，不伪装成功 |
| 7 | 修复阻塞问题、完成发布准备 | 可运行范围清晰，已知限制和未实现项有记录 |

### 13.1 按顺序降级

1. **优先延后 P1：**语音输入、额外格式、批量确认、样式精修和主题合并；保留 DOCX / TXT / MD / 粘贴。
2. **简化展示：**仅保留主题分组和阶段筛选，不做二维矩阵、图表或拖拽。
3. **缩小负载：**把验证规模降至 3 份较短访谈，界面明确限额；仍需支持多份和跨人聚合，不可静默截断。
4. **减少自动化：**阶段与主题允许人工补充，洞察逐个研究问题生成；不一次生成复杂长报告。
5. **模型始终不可用：**在研发验收中记录自动分析未通过，保留人工编辑与核对流程；产品侧只展示实际操作失败，不增加开发环境说明或独立模式标签。

**不可降级的要求：**真实运行状态、原文可追溯、引用硬校验、按受访者去重计数、来源与推断分离、人工确认、保存与导出、无密钥泄露。不能用假数据或不可点击的证据入口替代这些能力。

## 14. 发布与运行要求

发布前应区分“需求”“已实现”“已验证”和“待验证”，不得把需求描述当成已有 API 或已有功能。

发布资料应包含：

- 当前需求基线，以及明确记录变更原因的范围变更说明。
- 实际可运行的代码包和启动说明；原型如单独存在则标明哪些功能仅为展示。
- 基于真实实现撰写的技术说明：数据保存方式、模型接入入口、环境要求、已测运行环境和已知限制。
- 脱敏 / 合成的演示材料及预期结果，明确“示例”标签。
- 验收记录：逐项状态，尤其是模型接入、证据定位、人数和导出。
- 运行环境验证记录：真实接口文档、鉴权来源、前后端边界、文件 / 存储支持、限额、超时、结构化输出支持、实际运行结果。

更换运行环境时，重新验证模型调用、持久化、文件导入、证据定位和报告导出。环境适配不得破坏已有项目的数据关系；存在不兼容时应提供明确提示和迁移说明。

## 15. 定稿决策与待验证项

**已定稿：**研究问题驱动；背景人工确认；支持无大纲；大纲引导兼顾开放发现；单访谈多主题多阶段；跨人证据聚合；点击卡片右侧逐人展示原文并定位全文；严格引用与人数规则；洞察分层；人工编辑、确认、导出；面向单人研究工作的 MVP。

**默认实现决策：**文本优先、单份材料一名被访者、别名身份、本地持久化、一级历史项目管理、二级四步流程、仅下载 Markdown 洞察报告、语音与额外文本格式可延期。上述取舍围绕工作场景中的核心研究任务和 MVP 边界确定。

**开发前必须验证：**模型调用机制、实际接口与环境适配限制、目标环境保存能力、声明文本规模的实际耗时与上下文适配。语音兼容性仅影响 P1，不阻碍文字主流程。

### 本轮交互验收补充

- DOCX 正文读取后成为独立记录，分配可修改编号；损坏、加密或无可读文字时提示原因。
- 大纲问题标题下展示对应回答；无法匹配的段落保留待归类。
- 清理“嗯”后“不知道”等表达仍在，完整原文不变，证据位置不变。
- 调整整理稿不改写引用；替换原文清除旧整理结果并使下游待复核。
- 分析按问题方向聚合需求痛点；报告以连贯章节展现，可编辑、确认并回查证据。
